# Incident: red security gate on dev unnoticed across three merge windows (wallpaper picker's Openverse fetch)

- **Date:** 2026-10-10 (focus-board repo; detected by warrant child thread thr_2hmzyznvg2, ticket #25)
- **What happened:** Merge `f43c0c1` (wallpaper picker with a keyless Openverse search, thread thr_mqe3vsf3i2) landed on `dev` with `npm run gates` failing: `GATE VIOLATION: fetch( outside the audit-approved loopback daemon client → components/wallpaper-picker.tsx:215`. Two subsequent merges (`dae1f6f` seed ladder #24, `9b9a2f2` personal-filter fix #25) landed on the red gate the same day, so a security gate on the integration branch was red for the whole day. The thread that introduced the fetch ran `npm test` (97 files / 1451 tests green) and `npx tsc --noEmit` (clean) — both green — but its last two worktrees did not run `npm run gates`, and nothing else surfaced the violation.
- **Impact:** No data exposure. The fetch was bounded on review: a fixed keyless https host constant (`https://api.openverse.org`), operator input riding only as an `encodeURIComponent`-encoded query param, response read only through a schema-filtered parser (`parseOpenverseResults`). The impact was process, not data: the gate's guarantee — that every merge into dev leaves the security gates green — was unenforced, and the red rode invisibly under every later merge.
- **Detection:** Full-suite audit by warrant child #25 on the dev tip; the gate violation was the only red across tests, types, and gates.
- **Root cause (two layers):** (1) Merge gate discipline skipped `npm run gates` — twice by the introducing thread, and again by the threads that later merged onto the red. (2) No test in `npm test` knew about the gate's fetch allowlist, so a red gate was invisible to the suite every merge thread runs.
- **Impact windows (each re-landed the raw fetch from a branch that predated the fix, red gate each time, each caught by warrant thread thr_2hmzyznvg2):**
  1. `f43c0c1` (thr_mqe3vsf3i2) introduced the fetch at `wallpaper-picker.tsx:215` — red across `dae1f6f` and `9b9a2f2`.
  2. Paging merge `09e310a` (thr_gjhht96gmh, "Openverse re-search walks result pages") re-landed its branch's raw fetch at `wallpaper-picker.tsx:242` (`fetch(openverseSearchUrl(trimmed, page), …)` — page riding the wire).
  3. Wallpaper-polish merge `c51074f` (thr_epdi56wrrw) re-landed its branch's seam-less picker at `wallpaper-picker.tsx:258` on dev tip `9f21c96`.
- **Closing (completed):** merge `0794fe0` (thread thr_kcx6zgrrrg, "scoped security re-audit") landed the hardened client `lib/openverse.ts` — pinned `https://api.openverse.org` origin refused at call time by `requireOpenverseSearchUrl` (stronger than a host-constant builder alone: a later builder regression fails loud at the call site), no credentials/referrer, no redirects followed, 10s deadline composed with the caller's signal, payload read only through the tolerant parser boundary — with its own audit [`docs/security-audit-2026-10-10-openverse-client.md`](../security-audit-2026-10-10-openverse-client.md) and the gate allowlisting it. Dev tip gates green.
- **Honest supersession note:** the warrant thread's own parallel repair (an audited seam in `components/wallpaper-presets.ts`, `searchOpenverseImages` + gate allowlist structure extension, red-first pins) was mid-flight when `0794fe0` landed; it was dropped in place of the stronger origin-pinned client as part of this ticket's scope reduction. Both implementations followed the same audited pattern; keeping one, the stricter one, is the point of a gate. Coordination lesson for the runbook: when a red security incident warrants multiple repair threads, the overseer should demote or redirect the first repair as soon as a second thread starts the same finding — a superseded-in-flight repair is wasted work the warrant cannot see coming alone.
- **Standing backstop (completed):** `tests/security-fetch-seams.test.ts` scans shipped code for `fetch(` sites in the ordinary suite (which every merge thread runs) and requires each to sit inside an approved seam — it caught the identical violation shape at picker:242 during this incident. The seam table it enforces lives once, in `scripts/security-seams.mjs`, which `scripts/security-gates.mjs` also reads (refactor proven output-identical), so gate and suite cannot drift apart on a rename again. A text-pinned seam refuses other fetch shapes in its file; a seam file's deletion or rename breaks the suite immediately.
- **Prevention:** run `npm run gates` alongside `npm test` before every merge into dev — the suite backstop narrows, does not close, the gap: the gate still covers checks the suite does not replicate (npm audit, the non-fetch sinks, `window.open` noopener). And on a re-land: a feature branch merged onto a red gate may carry the violation again — re-run BOTH the gates and the suite after every dev merge.
- **Runbook:** the seam pattern for any new network fetch is documented at the top of the network section in `scripts/security-gates.mjs`; the table itself is `scripts/security-seams.mjs`; the closing audit is `docs/security-audit-2026-10-10-openverse-client.md`.
